## 2024-10-14 - Intra-request Duplicates in Batched Queries
**Learning:** When fixing N+1 query problems by replacing a sequential `findFirst` and `create` loop with batched `findMany` and `createMany` operations, intra-request duplicates (identical items within the same request array) can cause unique constraint violations or duplicate entries. The original sequential loop inherently prevents duplicates if the input contains identical items because each loop iteration checks the DB again, whereas a naive batched approach checks the DB once at the start and does not catch duplicates within the batch itself.
**Action:** Always use a `Set` (or similar mechanism) during the filtering/mapping step to explicitly track and skip intra-request duplicate entries when converting sequential DB operations into batched operations.
