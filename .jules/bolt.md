## 2026-10-12 - Prevent intra-request duplicates when fixing N+1 queries\n**Learning:** When refactoring a sequential findFirst/create loop into batched findMany/createMany queries, the new batch approach can accidentally insert duplicate rows if the original incoming payload contains duplicate items. The original loop prevents this inherently.\n**Action:** When fixing N+1 queries with batching, always ensure the `Set` used for filtering tracks and skips duplicates *within* the incoming request payload itself.
