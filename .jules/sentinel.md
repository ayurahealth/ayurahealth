## 2024-10-24 - Missing Authorization Check (IDOR) in Next.js API Routes
**Vulnerability:** The `/api/chat/history` endpoint accepts a `userId` query parameter and queries the database for chat sessions belonging to that user, but fails to verify if the currently authenticated user matches the requested `userId`. This allows any authenticated user (or unauthenticated, depending on middleware) to view the chat history of any other user (Insecure Direct Object Reference).
**Learning:** Next.js App Router API endpoints in this application do not enforce global authorization middleware. It's not enough that a route might be protected by Clerk middleware generally; if the route accesses user-specific resources based on user input, it must validate that the user has permission to access that specific resource.
**Prevention:** Always manually use `auth()` from `@clerk/nextjs/server` in each endpoint to retrieve the authenticated user's ID (`userId`) and validate any client-provided user IDs against it before returning sensitive data. Note that in Next.js 15+ / Clerk v7+, `auth()` is asynchronous and must be `await`ed.
