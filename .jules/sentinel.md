## 2024-05-18 - [CRITICAL] Removed CEO Authentication Bypass Vulnerability
**Vulnerability:** A hardcoded `CEO_BYPASS_KEY` in `process.env` allowed users to set an `ayura_ceo_token` cookie and bypass standard Clerk authentication/rate limiting across the application (chat, payments, clinic leads). This token was validated using a simple boolean check (`isCeo = Boolean(CEO_BYPASS_KEY && ceoToken === CEO_BYPASS_KEY)`) without secure role-based access control (RBAC).
**Learning:** Hardcoded "backdoors" or "bypass keys" for administrative access or local testing present a severe security risk, especially when the key can grant unlimited API access and circumvent rate limits. Even if documented as a "secret," they are prone to exposure and exploitation.
**Prevention:** Never use hardcoded bypass keys or tokens for administrative privileges. Implement a robust, standard Role-Based Access Control (RBAC) system tied to the main authentication provider (e.g., Clerk) to handle administrative roles. Ensure rate limits apply to all endpoints appropriately or are securely managed via user roles, not bypass cookies.
