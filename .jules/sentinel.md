## 2024-05-30 - Insecure Default Fallbacks in Payment Verification\n**Vulnerability:** Weak pseudo-random number generator (`Math.random()`) used for critical payment receipt IDs and vulnerable standard string comparison (`===`) used for verifying payment webhook signatures.\n**Learning:** Next.js Serverless APIs can easily mix client-side idioms (like `Math.random()`) with server-side logic if not carefully monitored. Node.js `crypto.timingSafeEqual` is crucial for signature validation to prevent timing side channels.\n**Prevention:** Mandate CSPRNG (`crypto.randomUUID()`) for all transaction identifiers. Enforce `timingSafeEqual` with strict buffer length checks for all secret/signature verification paths.
