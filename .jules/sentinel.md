## 2025-02-18 - Remove Hardcoded CEO Bypass Key Vulnerability
**Vulnerability:** A hardcoded `CEO_BYPASS_KEY` was used to create an `ayura_ceo_token` cookie, which allowed a user to bypass rate limits and potentially other security controls in the API. The token was read from cookies and checked against the environment variable in `app/api/chat/route.ts` and `lib/rateLimit.ts`. The route `app/api/auth/ceo-pass/route.ts` allowed any user with the correct key to set this cookie for themselves.
**Learning:** Hardcoded bypass keys (backdoors) for administrative or "CEO" access are extremely dangerous. They bypass standard authentication/authorization flows and, if leaked, give attackers unmetered access or elevated privileges. They should never be used, even as temporary solutions.
**Prevention:** Rely strictly on established, robust Role-Based Access Control (RBAC) mechanisms (like Clerk roles or permissions) for elevated access. Never implement custom bypass logic based on static keys or cookies.
