## 2026-09-29 - [CRITICAL] Prevent SSRF and DNS Rebinding (TOCTOU)
**Vulnerability:** The `/api/fetch-link` endpoint was using standard `fetch` with user-supplied URLs without verifying the IP, making it vulnerable to Server-Side Request Forgery (SSRF) and DNS rebinding (TOCTOU) attacks.
**Learning:** Preventing SSRF in Node.js/Next.js requires resolving the hostname with `dns.lookup` and validating the IP against private blocks (mapping IPv4-mapped IPv6 to IPv4 first). Native `fetch()` is insufficient because substituting the hostname with the resolved IP for HTTPS breaks TLS SNI (Server Name Indication) and certificate validation.
**Prevention:** Use a custom `http.request`/`https.request` implementation that overrides the connected IP address while preserving the original hostname for SNI (`servername`) and the HTTP `Host` header. Handle redirects manually (max 3 hops) and wrap operations in timeouts to prevent DoS. Use the `fetchWithSSRFProtection` utility instead of native `fetch` for any external user-supplied URL.
