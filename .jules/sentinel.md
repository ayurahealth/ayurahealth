## 2024-10-08 - Fixed IDOR in Chat History Endpoint
**Vulnerability:** Found an Insecure Direct Object Reference (IDOR) vulnerability in `/api/chat/history/route.ts` where the `userId` was accepted from URL search parameters without checking if it matched the currently authenticated user's ID. This would allow an authenticated attacker to view the chat histories of any other user simply by guessing or iterating their `userId`.
**Learning:** Next.js API routes with Clerk authentication often rely on middleware to enforce authentication, but the middleware itself does not map authorization for specific objects (like user-specific IDs). Developers might assume `userId` passed as a query param is safe if the route is protected by `clerkMiddleware()`. This codebase lacks global object-level authorization in API routes.
**Prevention:** Always extract `authUserId` from `@clerk/nextjs/server`'s `auth()` method (remember it is asynchronous in Next.js 15+ / Clerk v7+) in every API route that handles sensitive user data, and strictly validate that any client-provided identifiers match the authenticated context. Do not trust client-supplied `userId` parameters for authorization.
