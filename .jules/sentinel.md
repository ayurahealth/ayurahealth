## 2023-10-12 - [CRITICAL] Prevent Insecure Direct Object Reference (IDOR) in Next.js API Routes
**Vulnerability:** The `/app/api/chat/history/route.ts` API endpoint extracted `userId` from the URL query parameters and used it directly to query the database (`prisma.chatSession.findMany({ where: { userId } })`) without validating that the authenticated user matched the requested ID. Any authenticated user could supply another user's ID to view their private chat history.
**Learning:** Next.js App Router API endpoints in this application do not enforce global authorization middleware that binds requests to specific resource owners. Even if Clerk protects the route from unauthenticated access, authorization logic (resource ownership) must be handled explicitly within each endpoint.
**Prevention:** To prevent IDOR vulnerabilities when authenticating Next.js API routes with Clerk, manually use `auth()` from `@clerk/nextjs/server` in each endpoint to retrieve the authenticated user's ID (`authUserId`) and validate any client-provided user IDs against it before returning sensitive data. Return a `401 Unauthorized` response on mismatch.
